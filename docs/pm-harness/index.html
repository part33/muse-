Problem Definition

要解决的问题

AI 能写文档，但不一定能控产品

单次生成式 prompt 容易产出“看起来完整”的 PRD，但需求边界、用户价值和 MVP 范围常常没有被真正验证。

主要风险

  • 目标用户和使用场景模糊。
  • 第一版范围过大，功能堆叠。
  • 文档缺少评审，模糊描述被直接交接。
  • 关键取舍没有记录，后续难复盘。

我的解决方式

把 AI 产品定义拆成阶段化工作流，用 Harness 负责路由、门禁和回退，而不是只依赖一个“万能 PRD prompt”。

Workflow

运行逻辑

Operating Principle

先收敛，再生成；先评审，再交接。

这套流程把 AI 从“内容生成器”限制为“按阶段推进的产品协作者”，每一步都有明确输入、输出和完成标准。

  1. 1 · Clarify

    不直接写 PRD，先补齐用户、场景、问题和目标。

  2. 2 · Scope

    区分必须做、可以后置、本轮不做，控制 MVP。

  3. 3 · Build

    把收敛后的信息整理成结构化产品文档。

  4. 4 · Review

    独立评审文档质量，修正模糊和不可执行表达。

  5. 5 · Handoff

    把通过评审的 Spec 转成下一阶段可执行目标。
