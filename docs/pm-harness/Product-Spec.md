# Product Spec

## 1. 产品概述

### 1.1 产品定位
PM Harness 是一套面向 AI 产品经理工作的 workflow harness，用于把模糊想法转化为可评审、可执行、可交接的产品文档。

### 1.2 目标用户

- 正在使用 AI 辅助产品定义的独立开发者
- 需要快速收敛需求的小团队产品经理
- 希望提升 AI 文档产出质量的 workflow 设计者

### 1.3 核心价值
不是更快生成 PRD，而是通过阶段化澄清、范围控制和独立评审，让文档真正能进入下一阶段。

## 2. 问题定义

### 2.1 当前痛点

- 想法在澄清前就被直接写成文档
- 第一版范围容易失控
- 文档缺少独立评审
- 产品取舍没有记录，难以复盘

### 2.2 现有替代方案

- 直接用通用 LLM 写 PRD
- 使用模板型文档生成器
- 人工在多轮对话中零散整理需求

### 2.3 为什么现在做
AI 已经能生成大量产品内容，但缺少一套可控的产品定义结构。PM Harness 关注的不是生成速度，而是工作流可靠性。

## 3. MVP 范围

### 3.1 Must Have

- 需求澄清
- 市场范围判断
- MVP 收敛
- 产品文档生成
- 文档独立评审
- 交接目标生成

### 3.2 Nice to Have

- 更细粒度的 review 模板
- 面向设计阶段的 handoff 扩展
- 与外部调研工具的联动

### 3.3 Not In Scope

- 直接进入编码实现
- 自动完成所有产品决策
- 大而全的市场研究报告

## 4. 用户流程

1. 用户输入模糊产品想法
2. 系统先澄清产品定位、目标用户和核心场景
3. 系统判断现有替代方案与差异化
4. 系统收敛 MVP 范围
5. 系统生成结构化 Product Spec
6. 系统进行独立评审
7. 系统输出下一阶段 Handoff Goal

## 5. 功能需求

### 5.1 需求澄清
- 输入：原始想法
- 输出：澄清摘要

### 5.2 范围收敛
- 输入：候选功能和场景
- 输出：Must-have / Nice-to-have / Not-in-scope

### 5.3 文档生成
- 输入：已澄清内容
- 输出：Product-Spec.md

### 5.4 独立评审
- 输入：Product-Spec.md
- 输出：通过 / 需修改 + 问题列表

### 5.5 目标交接
- 输入：评审通过的 Product Spec
- 输出：下一阶段 Goal

## 6. 成功标准

- 文档可评审
- 文档可交接
- 功能范围有边界
- 关键决策可追溯

## 7. 风险与待确认问题

- 不同项目类型对 Product Spec 结构要求可能不同
- 交接目标模板可能需要按团队工作方式调整
